# EVIDENCE & VERIFICATION

**Phase 23 — Evidence Registry and Verification System**

## Evidence Registry

Every piece of evidence on Theek Karo is registered in the central evidence
registry with full metadata.

### Evidence Types

| Type | Description |
|------|-------------|
| `image` | Photos, screenshots |
| `video` | Video recordings |
| `document` | PDFs, scanned documents |
| `audio` | Audio recordings, voice notes |
| `text` | Written descriptions |
| `official_record` | Government-issued documents |
| `external_reference` | Links to external sources |

### Source Types

| Source | Authority Level |
|--------|----------------|
| `OFFICIAL_GOVERNMENT` | Highest — government-published data |
| `PUBLIC_DATASET` | High — curated public datasets |
| `OPEN_DATA` | High — open data portals |
| `INSTITUTION` | Medium — institution-reported |
| `ORGANIZATION` | Medium — organization-reported |
| `PARTNER` | Medium — partner organizations |
| `COMMUNITY` | Medium — community observations |
| `CITIZEN` | Standard — citizen submissions |
| `INTERNAL` | Platform-internal |
| `AI_GENERATED` | Generated by AI tools |
| `DERIVED_ANALYTICS` | Computed from other data |

### Evidence States

```
SUBMITTED → PROCESSING → UNDER_REVIEW → VERIFIED
                                           ↓
                                    PARTIALLY_VERIFIED
                                           ↓
                                      REJECTED / EXPIRED / SUPERSEDED
```

### Integrity

Every evidence record stores:
- **SHA-256 hash** of the content
- **Chain hash** for tamper-evident ordering
- **File size** and **MIME type**

The hash detects accidental or intentional changes but does NOT prove
the underlying content is truthful.

## Verification System

Verification is not binary. It supports multiple stages and methods.

### Verification Decisions

| Decision | Meaning |
|----------|---------|
| `NOT_REVIEWED` | No verification performed yet |
| `REVIEWED` | Looked at but not confirmed |
| `VERIFIED` | Confirmed by reviewer |
| `PARTIALLY_VERIFIED` | Some aspects confirmed |
| `DISPUTED` | Someone challenged the verification |
| `REJECTED` | Found to be inaccurate |

### Verification Methods

| Method | Description |
|--------|-------------|
| `human_review` | A person reviewed the evidence |
| `official_source_confirmation` | Confirmed against official records |
| `cross_source_consistency` | Multiple sources agree |
| `location_validation` | Location verified (GPS, address) |
| `timestamp_validation` | Timing verified |
| `document_verification` | Document authenticity checked |
| `duplicate_analysis` | Checked for duplicates |
| `structured_data_validation` | Schema and type validation |
| `ai_assisted` | AI provided analysis, human decided |

### AI Verification Assistance

AI may assist reviewers with:
- Duplicate detection
- Image similarity analysis
- Document extraction
- Metadata checks
- Inconsistency detection
- Summarization

AI must produce:
- Confidence score
- Reasoning
- Source references

**Human reviewers make final verification decisions.**

### Append-Only

Verification records are append-only. Every verification action is recorded
with reviewer, timestamp, method, evidence, decision, and explanation.
Historical verification records are never modified or deleted.

### Tamper-Evident Chain

Verification records include a chain hash computed from the previous hash
and the current record data. This creates a tamper-evident chain:

```
Record 1: hash(prev=GENESIS, data=...)
    ↓
Record 2: hash(prev=Record1.hash, data=...)
    ↓
Record 3: hash(prev=Record2.hash, data=...)
```

## Multilingual Evidence

Evidence preserves:
- **Original text** in the original language
- **Translated text** with target language

Translations never replace originals. Both are stored and displayed.

## Evidence for AI

When AI uses evidence, it must:
- Cite the source
- Note the verification status
- Acknowledge limitations
- Never claim unverified evidence is confirmed
