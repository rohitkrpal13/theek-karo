# INTERNATIONALIZATION (I18N)

**Project:** Theek Karo
**Version:** 1.0
**Date:** 2026-08-14
**Status:** Approved (Phase 1) — implementation Phase 7 (web) + backend catalogs

---

## 1. Strategy

**Hindi-first, English-parallel, regional follow.** The platform must be usable by a
user whose primary language is Hindi from day one, with English as the second locale, and
a defined path for additional Indian languages via community translation workflow.

- Launch locales: `hi` (Hindi, Devanagari), `en` (Indian English `en-IN` defaults).
- Follow-on locales (priority order): `ta`, `te`, `bn`, `mr`, `gu`, `kn`, `ml`, `pa`,
  `or`, `as`.
- All Indian target scripts are left-to-right; no RTL engineering required, but layout
  must tolerate font-metric differences (Devanagari ascenders).

## 2. Content Model

Two content classes with different trust handling (see DATABASE.md §3.3, AI-ARCHITECTURE.md §4.3):

| Class | Examples | Trust |
|-------|----------|-------|
| **UI/product strings** | Buttons, labels, errors, campaign titles | Source of truth in translation catalogs; reviewed by maintainers |
| **User content** | Report title/description, comments | Canonical in origin language; translations are derived content (T2/T4/T3 by kind) |

Rules:
- UI strings never live in the DB except campaign/category names, which use i18n **keys**
  (`category.school`, `campaign.xyz.title`) resolved per locale with fallback chain.
- User content: canonical + `report_strings` per-locale translations, each tagged with
  info_class; never silently machine-translated into the canonical record.

## 3. Implementation Plan (web, Phase 7)

- **Framework integration:** Next.js App Router with `next-intl` (or equivalent:
  file-based message catalogs with ICU MessageFormat; decision in ADR-021 during Phase 7).
- **Catalogs:** `apps/web/messages/{en,hi}.json` + `packages/shared` message keys shared
  with API-rendered strings; type-safe keys via generated types.
- **Locale resolution:** accept-language header → saved preference → default `hi` for
  India-first; language switcher on every page header (UX.md §7).
- **Pluralization/formatting:** ICU plurals; `en-IN` number formats with lakh/crore
  grouping (1,00,000) — distinct from US grouping; dates in Indian-friendly formats
  (DD MMM YYYY, 24-h clock default).
- **Fonts:** Noto Sans Devanagari + Latin stack; subset latin+devanagari to keep payload
  ≤ 40 KB per variant; `font-display: swap`.

## 4. Backend i18n (Phase 7+)

- `tk_api.i18n` module: locale catalog endpoint `GET /api/v1/i18n/catalog?locale=hi`
  (versioned, cached in Redis; supports offline-first clients).
- API error details provide both machine `type` and human `title_key` (locales resolved
  client-side to avoid server-rendered-language coupling).
- Notifications (Phase 8): templates stored per locale with fallback chain
  (`hi` → `en`), rendering server-side at dispatch time.
- Numeric/unit conventions: UTC stored, local display converted client-side.

## 5. Community Translation Workflow

- New/updated UI strings and campaign content enter a review queue (`translations`
  table: `review_status = pending|reviewed`; reviewer role `volunteer`/`admin`).
- Translators volunteer role; suggestions tracked with credit; quality gate: reviewed
  translations promote over auto/robo suggestions.
- Machine-translation assist (T4 tag) is allowed as a *suggestion*, never auto-published.
- Coverage dashboard: % locale coverage of the catalog per locale.

## 6. AI-Assisted Translation Guardrails

- LLM translation of user content: stored as `report_strings` with `info_class =
  AI_ANALYSIS`, confidence reported (AI-ARCHITECTURE.md §7 envelope).
- If community-verified translation exists, AI version is never shown by default.
- Transliteration (Devanagari↔Latin) treated as T4 unless reviewed.

## 7. Locale Data & QA

- Locale test suite: key coverage check (no missing keys per locale in CI), ICU
  plural/format snapshots, Devanagari rendering smoke test in Playwright (Phase 7).
- QA drafts in both `hi` and `en`; translation completeness blocks release per locale
  (release gates in ROADMAP Phase 7).

## 8. Out of Scope (later)

- RTL locales (no Indian launch requires it), full ICU in SMS channels (provider limits),
  offline translation dictionaries.
